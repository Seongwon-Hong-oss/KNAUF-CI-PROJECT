# KNAUF 2026 CI KAiZEN CIRCLE | 멤버 맛집·주차장 지도

React + TypeScript + Kakao Maps + Supabase 기반 모바일 웹 앱. 제공된 크나우프 로고와 파란색 테마를 적용했으며 Vercel에서 정적 웹 앱으로 배포할 수 있습니다.

## 현재 가능한 기능

- 장소 종류 선택 후 상호명 검색(예: 스타벅스 강남점), 주소 입력 또는 지도에서 위치 선택으로 맛집·주차장 등록 (위·경도 입력 없음, 주소는 필수). 선택한 위치는 핀으로 먼저 보여주고 확인 후 등록 화면으로 넘어갑니다.
- 파란색 식당 핀과 남색 P 핀, 종류 필터, 이름·주소·메모 검색
- 추천 메모, 가격 또는 추가 요금 안내(선택, 예: 시간당 3,000원 / 최초 30분 무료), 댓글, 장소 수정·삭제
- 장소별 좋아요(계정당 1회, 다시 누르면 취소)
- 주차장 요금 구조화 입력(무료/유료, 30분당 요금, 무료 시간)
- 장소 상세의 **이용했어요** 기록(실제 낸 주차비와 평소 주차비는 선택 입력, 둘 다 입력하면 절감액 = 평소 − 실제)
- 처음 로그인 시 월평균 주차비 설문(건너뛰기 가능, 대시보드에서 도입 전·후 금액 입력). 평균은 응답 3건 이상일 때만 표시하고 개인 응답은 다른 멤버에게 보이지 않습니다.
- 대시보드 **성과 지표(KPI)**: 이번 달 이용 건수·추정 절감액, 참여율, 서울 25개 구별 주차장 등록 현황, 도입 전·후 월평균 주차비, 월별 표, 목표 달성률(목표값은 관리자가 입력), CSV 내보내기
- 장소별 “네이버 지도 앱으로 길 안내” 버튼: 모바일에서 네이버 지도 앱의 내비게이션(`nmap://navigation`)을 바로 열어 목적지를 설정하고, 앱이 없으면 스토어로 이동합니다. PC에서는 네이버 웹 지도를 엽니다.
- 장소별 네이버 지도 검색 및 구글 지도 좌표 링크
- 현재 위치 이동, 본인 댓글 삭제
- 모바일은 지도를 전체 화면으로 두고 장소 목록·상세를 하단 시트로 표시
- 처음 접속 시 크나우프 로고와 `2026 CI KAiZEN CIRCLE`만 보이는 로그인 화면. 계정(일반 ID)·비밀번호로 로그인
- 계정 등록은 이름·사무소(Seoul office / Busan office / Gwangju office / Daejeon office / Daegu office / Ulsan Plant / Dangjin Plant / Yosu Plant 드롭다운)·계정·비밀번호만으로 완료. 계정이 중복되지 않으면 바로 등록 (이메일·이메일 인증·관리자 승인 없음, 대소문자 구분 없음)
- `Admin` 계정으로 등록한 사람은 자동으로 관리자가 됩니다.
- 대시보드(모든 멤버 열람 가능, 관리자 계정은 표시되지 않음): 멤버 수, 장소 수, 이용 중 멤버 수, 가장 많은 좋아요를 받은 장소·멤버, 가장 많이 등록한 멤버(각 TOP 3), 멤버별 등록 수와 기여율. 접근 중지·재개는 관리자만 가능
- 즐겨찾기는 각 브라우저에 저장. 장소·멤버·댓글은 Supabase 연결 시 공용 데이터베이스에 저장

네이버/구글 지도는 **외부 링크**입니다. 앱 안의 지도는 **카카오맵 JavaScript SDK**이며, 상호명 검색·주소 ↔ 좌표 변환도 카카오 로컬 서비스를 사용합니다.

카카오맵 설정:

1. [Kakao Developers](https://developers.kakao.com)에서 앱을 만들고 **제품 설정 > 카카오맵**을 활성화합니다(첫 번째로 활성화한 앱만 일간 무료 쿼터 제공).
2. **앱 설정 > 플랫폼 키 > JavaScript 키**의 사이트 도메인에 배포 주소와 `http://localhost:5173`을 등록합니다.
3. JavaScript 키를 `VITE_KAKAO_JS_KEY` 환경변수(`.env.local`, Vercel)에 넣습니다. 등록한 도메인에서만 쓸 수 있는 키이며 REST 키는 앱에 넣지 마세요.

## 무료 이용에 대한 주의

비상업적 목적으로 운영한다는 전제에서 Vercel Hobby(무료)로 배포할 수 있습니다. **Vercel Hobby는 개인·비상업 용도만 허용합니다.** 이용 목적이 바뀔거나 회사 업무용으로 판단될 수 있다면 Vercel 정책을 다시 확인하거나 Pro를 검토하세요. 회사 이용 정책이 있는 경우 그에 따라야 합니다. 유료 결제나 실제 배포는 자동으로 하지 않았습니다.

- [Vercel Hobby 정책](https://vercel.com/docs/plans/hobby)
- [Supabase 무료 플랜](https://supabase.com/pricing): 무료 범위 내 이용 가능. 500MB DB, 50,000 월간 활성 사용자, 5GB 송신량, 비활성 1주 후 프로젝트 일시정지 가능. 정책은 바뀔 수 있습니다.
- [Kakao Maps API](https://developers.kakao.com/docs/latest/ko/getting-started/quota): 지도 표시와 장소·주소 검색에 사용. 일간 무료 쿼터는 첫 번째로 활성화한 앱에만 제공되며 약관·쿼터는 바뀔 수 있습니다.
- 이메일을 쓰지 않으므로 가입 메일 발송이 없어 SMTP 설정과 발송 한도 문제가 없습니다.
- 멤버 이름·사무소와 해외 클라우드 저장은 회사 개인정보·보안 정책 검토 후 사용하세요. 이 앱은 공식 사내 SSO 연동이 아닙니다.

## 로컬 실행

Node.js 22.12 이상 또는 지원되는 최신 LTS를 설치한 뒤 프로젝트 폴더에서 실행합니다.

```powershell
npm install
npm run dev -- --host 0.0.0.0
```

기본 주소는 http://localhost:5173/ 입니다. 동일 Wi-Fi 휴대폰은 터미널에 표시되는 Network 주소로 접속할 수 있습니다. 방화벽에 따라 차단될 수 있으며 현재 위치 기능은 HTTPS 또는 localhost에서 사용하세요.

**환경변수가 없으면 로컬 데모 모드입니다.** 로그인 화면은 동일하게 나오며 관리자 테스트 계정 `Admin` / `1234567890`으로 로그인하거나 새 계정을 등록해 사용합니다. 예시 장소와 멤버는 가상 데이터이고, 계정과 비밀번호 해시는 이 브라우저의 localStorage에만 저장되는 테스트용이라 실제 보안 인증이 아닙니다. 실제 운영 전에 반드시 Supabase를 연결하세요. 로컬 데모 데이터는 실제 DB로 자동 이전되지 않습니다.

이번 작업에서 Node.js는 관리자 설치 없이 `%LOCALAPPDATA%\team-map-tools`에 준비했습니다. 새 터미널에서 명령을 못 찾으면 일반 Node.js LTS 설치 또는 아래 세션 경로 설정을 사용하세요.

```powershell
$nodeHome = (Get-ChildItem "$env:LOCALAPPDATA\team-map-tools\node-v22*-win-x64" -Directory | Select-Object -First 1).FullName
$env:Path = "$nodeHome;$env:Path"
```

## Supabase 실제 공유 모드 설정

1. 회사에서 사용할 Supabase 프로젝트를 만들고 지역·개인정보 보관 정책을 확인합니다.
2. 새 프로젝트 SQL Editor에서 [supabase/schema.sql](supabase/schema.sql), [002](supabase/002_instant_signup_ratings.sql), [003](supabase/003_optional_address.sql), [004](supabase/004_account_login.sql), [005](supabase/005_likes.sql)을 **순서대로 각각 한 번** 실행합니다. 이어서 [006](supabase/006_keepalive.sql)(선택, DB 연결 유지용 함수)과 [007](supabase/007_kpi.sql)(주차장 요금 컬럼, 이용 기록·설문·목표 테이블)을 실행합니다. 기존 버전 DB는 아직 적용하지 않은 번호의 파일만 실행합니다. 005는 좋아요 테이블을 추가합니다(생략하면 앱이 좋아요를 불러오지 못해 장소 목록이 비어 보일 수 있습니다). 002는 즉시 가입 기본값과 현재 앱에서 쓰지 않는 별점 테이블·시간당 주차비 컬럼(무해하며 그대로 두어도 됩니다), 003은 선택 주소, 004는 이메일 도메인 제한 제거·계정 ID·사무소 제한·`Admin` 자동 관리자 지정을 적용합니다. 004는 사무소 제한을 신규 등록에만 적용하므로 기존 프로필은 그대로 둡니다. 기존에 접근 중지한 멤버도 002로 활성화되므로 필요하면 다시 중지하세요. 재실행용 스크립트는 아닙니다.
3. 이전 버전의 `company_domains` 테이블은 더 이상 사용하지 않습니다.

4. [.env.example](.env.example)을 참고해 `.env.local`에 Project URL과 **publishable 또는 legacy anon key**를 설정합니다. `service_role` 또는 secret key는 절대 `VITE_` 환경변수에 넣지 마세요. 개발 서버를 재시작합니다.
5. Supabase Authentication > Sign In / Providers > Email에서 이메일 로그인을 켜고 **Confirm email(이메일 인증)을 끕니다.** 이 설정이 켜져 있으면 가입 직후 로그인되지 않고 “이메일 인증이 켜져 있습니다” 오류가 표시됩니다. 비밀번호 최소 길이는 앱과 맞게 6자 이상으로 둡니다.
6. 멤버는 이름·사무소·계정·비밀번호로 등록하고 바로 이용합니다. **이메일과 관리자 승인은 없습니다.** Supabase가 이메일 형식 로그인만 지원하므로 앱이 계정 ID를 해시해 `u<해시>@ci-project.app` 같은 내부용 주소로 변환해 사용합니다. 이 주소로는 메일을 보내지 않습니다. 만약 가입 시 “계정 설정 오류”가 나오면 Supabase가 이 도메인을 거부한 것이므로 `VITE_ACCOUNT_DOMAIN`에 본인이 소유한 도메인을 설정하고 재배포하세요. 이 값을 나중에 바꾸면 기존 계정으로 로그인할 수 없으므로 배포 전에 정하세요. 계정을 아무나 만들 수 있고 다른 사람이 쓰는 계정을 선점할 수도 있습니다.
7. 관리자는 배포 직후 앱에서 `Admin` 계정을 **가장 먼저** 등록하면 되고 자동으로 관리자가 됩니다. 다른 사람이 먼저 등록하면 그 사람이 관리자가 되므로 주의하세요. 비밀번호 `1234567890`은 추측하기 쉽습니다. 공개 URL 배포 전에 더 긴 비밀번호를 쓰길 권장합니다.

8. 관리자가 로그인하면 멤버 기여 현황과 접근 중지·재개를 관리할 수 있습니다. 다른 멤버의 새 장소·댓글·좋아요는 새로고침 버튼으로 불러옵니다.

## Vercel 배포

1. 비상업적 용도인지 확인하고 Vercel Hobby 약관과 회사 정책을 확인합니다.
2. 프로젝트를 GitHub 저장소에 올리고 Vercel에서 Import 합니다. Git 커밋이나 저장소 생성은 이 작업에서 하지 않았습니다.
3. 이 폴더를 포함한 상위 저장소라면 Root Directory를 `team-map`으로 지정합니다.
4. Framework: Vite, Build: `npm run build`, Output: `dist`. [vercel.json](vercel.json)에 동일한 설정이 있습니다.
5. Vercel Environment Variables에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_KAKAO_JS_KEY`를 등록하고 배포합니다. 환경변수 변경 후 재배포가 필요합니다.
6. 배포 URL로 접속해 로그인 화면이 나오는지 확인하고, 실제 계정 등록·로그인·장소 등록을 테스트합니다. 환경변수가 누락되면 앱이 로컬 모드로 배포되어 계정과 장소가 각 브라우저에만 저장되고 `Admin` / `1234567890` 테스트 계정으로 누구나 로그인할 수 있습니다. 로그인 후 관리 화면이 멤버 모두의 데이터를 보여주지 않는다면 Vercel 환경변수를 다시 확인해 재배포하세요.

외부 계정 생성, 키 발급, 실제 Vercel 배포는 아직 수행하지 않았습니다. 운영 전에 관리자·일반 멤버·접근 중지 멤버 각각의 실제 계정으로 확인해야 합니다.

## 보안과 기여율

신규 계정은 자동 활성화되며 이메일 도메인이나 승인 절차는 없습니다. 기존 `approved` 필드는 호환성을 위해 유지하며 이제 접근 중지 상태를 표현합니다. 신규 가입 메타데이터로 역할을 지정할 수 없고 `Admin` 계정만 관리자로 지정됩니다. 접근 중지 멤버와 로그아웃 사용자는 공용 장소·댓글·좋아요를 읽을 수 없습니다. 장소 수정·삭제는 작성자 또는 활성 관리자만 가능합니다. 좋아요는 DB 복합 기본키로 장소당 계정별 1개만 저장하며 본인 것만 취소할 수 있습니다. 멤버에게는 이름·사무소가 공유됩니다. 접근 중지는 이후 DB 요청을 막지만 이미 읽어둔 데이터까지 회수하지는 못합니다.

기여율 = 멤버의 현재 장소 등록 수 / 현재 전체 장소 수 × 100. 참여율 = 장소를 1곳 이상 등록한 활성 멤버 수 / 활성 멤버 수 × 100. 댓글과 좋아요는 기여율에 포함하지 않습니다. 삭제된 장소는 등록 수에서 제외하고 반올림하므로 멤버 기여율 합계가 정확히 100%가 아닐 수 있습니다. 현재 구현은 소규모 팀 MVP로 전체 데이터를 불러오며, Supabase API 기본 최대 행 수(보통 1,000행)를 넘기 전에 페이지네이션·서버 통계가 필요합니다.

```powershell
npm test
npm run lint
npm run build
```

[tests/database.test.mjs](tests/database.test.mjs)는 PGlite PostgreSQL 엔진에서 계정 ID 가입, `Admin` 자동 관리자 지정, 중복 계정 차단, 사무소 제한, 중지 계정 접근 차단, 관리자 권한, 좋아요 고유성·작성자 위조 방지, 주차 요금 범위 및 댓글 연쇄 삭제를 검증합니다. 실제 Supabase 이메일 발송·배포 환경을 대체하는 테스트는 아닙니다.
